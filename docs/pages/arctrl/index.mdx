`ARCtrl` is a software library to work with Annotated Research Contexts (ARCs). 
It contains an in-memory representation of an ARC and loads of functions to 
- manipulate and build both the ARC and its subcomponents
- read and write different representations, including the ARC Scaffold and ARC-RO-Crate

:::tip
If you're not sure about the ARC concept, check out [arc-rdm.org](https://arc-rdm.org/details/organization-principle/)
:::



By transpilation from the `F#` source code using [Fable](https://fable.io/), it is not only hosted on `nuget`, but also available as a JavaScript package on `npm` and as a python package on `PyPI`.

## What ARCtrl Is Not

ARCtrl is not a spreadsheet UI, a full DataHUB client, or a validator runner.
Those tools can build on ARCtrl, but ARCtrl itself focuses on the model,
serialization, spreadsheet conversion, and storage contracts.

## Main Capabilities

Use ARCtrl when an application needs to create or update ARC metadata without
hand-editing xlsx sheets or JSON documents. The central model types are
`ARC`, `ArcInvestigation`, `ArcStudy`, `ArcAssay`, `ArcRun`, `ArcWorkflow`,
`ArcTable`, and `Datamap`.

The common workflows are:

- build ISA metadata objects in memory
- create and edit annotation tables
- convert investigations, studies, assays, and datamaps to xlsx workbooks
- serialize native ARCtrl JSON or ISA-JSON
- inspect an ARC file tree and request read/write contracts
- attach runs, workflows, datamaps, templates, and validation-package metadata

The portable IO examples in this documentation prefer `JsonController`,
`XlsxController`, and `ARC` contract APIs because those are available from the
public roots in F#, TypeScript, and Python.

## First Check

Start with the setup page to verify that the package imports from the public
